# Information Security

Governance, risk, compliance, policy, awareness and incident response - the management side of security that turns technical controls into an organizational program.

> [!NOTE]
> This category covers defensive / governance topics. All material is for authorized use, education and certification preparation only.

---

## Scope

This category covers the non-technical (or cross-technical) disciplines that every security program needs:

- Governance: who decides, who is accountable, what frameworks apply.
- Risk: how risk is identified, assessed, treated and reported.
- Compliance: which laws and standards apply and how to prove conformity.
- Policy: what the organization requires of its people and systems.
- Awareness: how people learn to recognize and report threats.
- Incident Response and Business Continuity: how the organization detects, responds and recovers.

Technical depth (exploitation, tooling, detection engineering) lives in the other categories. This category links to them where the process depends on a technical control.

## Format

Files in this category use the **process-based** format (see the category layout): each file follows the process, not the attack/defense split. Every file includes:

- Overview and scope.
- Where in the organization the process sits.
- Threats and failure modes.
- Controls and implementation.
- Tooling.
- Verification and metrics.
- Anti-patterns.
- Certification Alignment.
- References.
